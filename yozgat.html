Databases

Deploys happen around your database.

Ship as often as you like. The database keeps running through all of it. Connect an app to it and the connection details are already there.

It gets backed up on its own schedule, and the copy leaves the server. You don't write a backup script.

App catalog

Your app and its services, drawn as they actually run.

The app deploys and redeploys. The services underneath it don't: they're attached once, from a catalog that also has MySQL and MongoDB.

Team & permissions

One root account. Exactly the access everyone else needs.

Preview environments

Every pull request gets its own environment.

Push a branch, get a URL. Close the PR and the environment, plus anything it cloned, is torn down on its own. Nothing lingers on disk waiting to be noticed.

Anything, anywhere

      
Any source, shipped the same way.

Connect a repository

          
Yozgat clones over SSH and builds on the server. It never calls a provider API, so GitHub, GitLab, Gitea, Forgejo and Codeberg all behave identically.

          

        

        

          
$ y link --repo git@github.com:acme/api.git

          
$ y publish

A backup every night, off the server

        
You don't set up a cron job or write a dump script. It runs on its own, and the copy leaves the machine. A backup on the same disk disappears with it.

The server reboots. Nothing is confused.

        
Power loss in the middle of a deploy is the worst moment for it. Yozgat checks what is actually running when it starts, and puts the last working version back.
